# rmrm.me 网站项目准备目录

## 目录定位

`rmrm_me` 是 `rmrm.me` 网站第一版的独立项目准备目录。

这个文件夹当前暂时放在 Flutter App 项目根目录下，后续会被整体移出，成为一个独立的网站项目。为了方便迁移，本轮与网站相关的所有规划文档、开发说明和后续网页源码都应只放在 `rmrm_me/` 内，不要散落到 App 项目的 `docs/`、`lib/`、`web/` 或其他目录。

当前阶段只做网站规划文档，不开发网页源码，不创建服务器，不接数据库，不做登录、支付、社区、AI 聊天或复杂后台。

## 网站第一版定位

`rmrm.me` 第一版不是一个复杂公司官网，也不是内容平台。它首先是一个可信、清楚、能快速上线的个人品牌主页。

网站核心定位：

```text
润木同学的个人品牌主页 + 第一个产品「润木听听」的正式入口
```

品牌关系：

```text
润木同学 = 个人品牌 / 创作者身份
润木听听 = 第一个 App 产品
亲子英语包播放器 = 润木听听的产品品类说明
rmrm.me = 润木同学和润木听听的官方落点
```

首页主表达建议：

```text
我在用 AI 做一些自己真的会用的小工具。
```

这句话比“AI 教育品牌”“家庭英语解决方案”“智能学习平台”等表达更真实，也更符合当前阶段。网站要让用户感受到：这是一个真实的人在认真做产品，而不是一个包装很重但还没有验证的商业项目。

## 第一版服务目标

第一版网站主要服务三个目标：

1. 给内测用户一个可信落点。

   用户从 App、社交平台、朋友转发或应用市场看到“润木同学 / 润木听听 / rmrm.me”时，可以打开网站确认这是什么项目、是谁做的、为什么做。

2. 给应用市场审核提供基础页面。

   `privacy.html` 和 `support.html` 后续需要作为隐私政策、支持与反馈入口使用。它们必须是独立页面，URL 清晰，内容稳定，方便应用市场填写和审核访问。

3. 给“润木同学”长期运营提供主页。

   你后续可能不止做一个 App。`rmrm.me` 应该承接长期个人品牌，而不是只绑定单一产品。第一版先展示“润木听听”这个作品，未来可以继续扩展更多小工具、开发记录或产品复盘。

## 第一版页面范围

计划第一版包含 5 个静态页面：

```text
index.html      润木同学首页
tingting.html   润木听听产品页
about.html      关于润木同学
privacy.html    隐私政策
support.html    支持与反馈
```

页面优先级：

1. `index.html`
2. `tingting.html`
3. `privacy.html`
4. `support.html`
5. `about.html`

如果时间非常紧，至少要保证首页、隐私政策页和支持页可以访问。

## 第一版技术路线

推荐第一版使用纯静态网页：

```text
HTML
CSS
少量 JavaScript
```

技术原则：

- 不引入 React、Vue、Next.js 或复杂前端框架。
- 不引入构建工具。
- 不需要数据库。
- 不需要自建服务器。
- 不需要对象存储。
- 不需要后台管理系统。
- 不需要登录注册。
- 不需要评论、社区、用户系统。
- 不需要复杂动画。

少量 JavaScript 只允许用于：

- 移动端菜单展开/收起。
- 当前年份显示。
- 简单的页面增强交互。

如果不用 JavaScript 也能完成，就优先不用。

## 视觉方向

第一版视觉方向选择：

```text
科技清爽为主，少量木色和绿色作为品牌点缀。
```

推荐气质：

- 干净。
- 可信。
- 克制。
- 有个人开发者真实感。
- 有产品感。
- 不像儿童培训机构。
- 不像重包装 AI 公司。

建议不要走浓重蓝紫渐变、炫技动画或大面积卡通风。头像和 App 图标可以出现，但不要铺满页面，否则会削弱网站的专业感。

## 反馈入口

第一版反馈入口使用飞书表单。

原因：

- 不需要自建服务器。
- 不需要数据库。
- 不暴露飞书 API token。
- 内测问题可以结构化收集。
- 适合个人开发者快速启动。

支持页后续应放置：

```text
飞书表单链接
反馈说明
可选联系邮箱
```

反馈内容建议收集：

- 手机型号。
- 系统版本。
- App 版本。
- 遇到的问题。
- 播放是否稳定。
- 哪个英语包或场景有问题。
- 是否愿意继续反馈。

不要收集儿童个人信息。

## 隐私原则

隐私政策页必须与当前 App 真实状态一致。

当前 App 原则：

- 不做登录。
- 不做注册。
- 不收集通讯录。
- 不收集定位。
- 不收集相册。
- 不收集摄像头。
- 不申请麦克风权限。
- 不接广告 SDK。
- 不接第三方分析 SDK。
- 收藏、播放记录、设置优先保存在本地设备。

如果后续增加匿名统计、付费、用户自定义英语包、音色服务或云端能力，必须同步更新隐私政策和相关说明。

## 部署方向

第一版部署推荐：

```text
Cloudflare Pages
或
Vercel
```

这两种方式都适合纯静态站，能较快绑定 `rmrm.me` 并开启 HTTPS。

第一版暂不需要：

- TOS 存储。
- 云服务器。
- 数据库。
- 自建 API。

如果后续要做用户行为数据、反馈接口、内容下载或付费校验，再单独设计轻后端。

## 给后续开发者或 Agent 的提醒

开发 `rmrm.me` 网站时，请始终记住：

```text
这是润木同学的个人品牌主页，也是润木听听的官方入口。
第一版目标是可信、清楚、能上线，不是复杂官网。
```

不要擅自添加：

- 登录。
- 注册。
- 社区。
- 评论。
- 支付。
- 会员。
- AI 聊天。
- 在线英语包市场。
- 用户上传。
- 后台管理。
- 数据库。
- 广告。
- 复杂动画。

如果某个功能不能帮助用户更快理解“润木同学是谁、润木听听是什么、如何反馈、隐私政策在哪里”，第一版就先不要做。
