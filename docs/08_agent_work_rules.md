# 后续开发 Agent 工作规则

## 1. 本文档用途

本文档给后续负责 `rmrm.me` 网站开发的开发人员或 agent 使用。

`rmrm_me/` 当前暂时位于 Flutter App 项目根目录下，但它会被整体移出，成为独立网站项目。因此，后续所有网站相关工作都必须保持边界清晰。

核心规则：

```text
只做 rmrm.me 网站。
只修改 rmrm_me/ 内的文件。
不要修改 Flutter App 项目。
不要把网站做成复杂系统。
```

## 2. 项目定位

`rmrm.me` 第一版网站定位：

```text
润木同学的个人品牌主页 + 第一个产品「润木听听」的正式入口
```

品牌关系：

```text
润木同学 = 个人品牌 / 创作者身份
润木听听 = 第一个 App 产品
亲子英语包播放器 = 润木听听的品类说明
rmrm.me = 官方网站 / 可信落点
```

网站第一版不是：

- 公司官网。
- 课程官网。
- AI 教育平台。
- 内容社区。
- 在线学习平台。
- App 后台。
- 用户中心。
- 支付系统。
- 博客系统。

第一版的目标是：

- 让用户知道润木同学是谁。
- 让用户知道润木听听是什么。
- 提供隐私政策。
- 提供支持与反馈入口。
- 为内测和应用市场审核提供可信链接。

## 3. 工作边界

### 3.1 允许修改

只允许修改：

```text
rmrm_me/
```

包括后续可能创建的：

```text
rmrm_me/index.html
rmrm_me/tingting.html
rmrm_me/about.html
rmrm_me/privacy.html
rmrm_me/support.html
rmrm_me/assets/
rmrm_me/docs/
```

### 3.2 不允许修改

不要修改当前 Flutter App 项目的以下目录或文件：

```text
lib/
android/
ios/
assets/data/
assets/audio/
scripts/
test/
pubspec.yaml
AGENTS.md
docs/
README.md
```

除非用户明确要求更新 App 项目，否则网站任务不得触碰这些文件。

特别注意：

- 不要使用 Flutter 项目的 `web/` 目录做网站。
- 不要把网站源码放到 App 的 `web/` 目录。
- 不要把网站文档放到 App 的 `docs/` 目录。
- 不要修改 App 的品牌文案、页面、图标或功能。

## 4. 技术规则

第一版网站使用：

```text
纯 HTML
纯 CSS
少量 JavaScript
```

不使用：

- React。
- Vue。
- Next.js。
- Nuxt。
- Astro。
- Vite。
- Tailwind。
- Bootstrap。
- UI 组件库。
- Node 后端。
- 数据库。
- CMS。
- 复杂构建流程。

如果后续确实需要升级技术栈，必须先重新制定计划，不要在第一版直接引入。

## 5. 页面范围

第一版只做 5 个页面：

```text
index.html      润木同学首页
tingting.html   润木听听产品页
about.html      关于润木同学
privacy.html    隐私政策
support.html    支持与反馈
```

不要擅自新增：

- 博客页。
- 文章系统。
- 登录页。
- 用户中心。
- 定价页。
- 支付页。
- 在线播放器页。
- 英语包市场页。
- AI 聊天页。
- 后台管理页。

如果用户后续要求新增页面，也应先确认页面目标和边界。

## 6. 功能禁止范围

第一版网站不得新增：

- 登录。
- 注册。
- 用户账号。
- 评论。
- 社区。
- 点赞。
- 排行榜。
- 会员。
- 订阅。
- 支付。
- 订单。
- AI 聊天。
- 在线生成英语句子。
- 用户上传英语包。
- 在线英语包市场。
- 数据库。
- 后台管理。
- 广告。
- 第三方复杂统计。
- 复杂动画。

网站第一版只是静态信息站。

## 7. 设计原则

视觉方向：

```text
科技清爽为主，少量木色和绿色作为品牌点缀。
```

设计关键词：

- 清爽。
- 可信。
- 克制。
- 移动端友好。
- 有产品感。
- 有真实个人开发者气质。

不要做成：

- 儿童培训机构风。
- 早教课程销售页。
- 炫酷 AI 科技站。
- 大面积蓝紫渐变。
- 大面积卡通插画。
- 复杂滚动动画网站。

移动端优先。内测用户大概率从手机打开网站。

## 8. 文案规则

必须保持以下表达一致。

网站主表达：

```text
我在用 AI 做一些自己真的会用的小工具。
```

产品表达：

```text
润木听听
给英语一般的爸妈用的亲子英语包播放器。
```

产品边界：

```text
它不是英语课程，不打卡、不测评，也不制造学习压力。
```

产品灵魂：

```text
爸妈先开口，孩子自然听见。
```

不要使用学习平台词汇：

```text
课程
学习
训练
打卡
等级
测评
排行榜
社区
AI 老师
发音评分
```

如果必须提到“学习”，需要非常谨慎，优先改成：

```text
听几句
说一句
亲子场景
英语包
播放器
```

## 9. 隐私和支持规则

隐私政策必须真实反映当前 App 状态。

当前原则：

- 不登录。
- 不注册。
- 不申请麦克风。
- 不申请定位。
- 不申请通讯录。
- 不申请相册。
- 不申请摄像头。
- 不接广告 SDK。
- 不接第三方分析 SDK。
- 收藏、播放记录、当前英语包、设置优先保存在本地设备。

支持入口第一版使用：

```text
飞书表单
```

禁止：

- 在前端暴露飞书 API token。
- 自建反馈接口。
- 要求用户登录后反馈。
- 公开展示用户反馈。
- 收集儿童敏感个人信息。

支持页必须提醒：

```text
请不要提交孩子的姓名、照片、学校等敏感个人信息。
```

## 10. 代码风格

第一版代码要简单。

HTML：

- 使用语义化标签。
- 每页有明确 `title` 和 `description`。
- 图片有 `alt`。
- 链接路径清楚。
- 页面结构易读。

CSS：

- 放在 `assets/css/style.css`。
- 使用少量 CSS 变量。
- 保持选择器简单。
- 移动端优先。
- 不写复杂动画。
- 不使用框架类名堆砌。

JavaScript：

- 能不用就不用。
- 如果使用，放在 `assets/js/`。
- 只做轻量增强。
- 不接第三方复杂脚本。

文件命名：

- 使用小写英文。
- 使用连字符或简单单词。
- 不使用中文文件名。

## 11. 链接规则

第一版内部链接优先使用相对路径：

```text
index.html
tingting.html
about.html
privacy.html
support.html
```

这样本地双击也能打开。

部署后如需无后缀 URL，再由部署平台配置重写。

外部链接：

- 飞书表单链接正式上线前必须替换。
- 不要使用假下载链接。
- 不要链接到不存在的 App 市场页面。
- 不要链接到未准备好的社交平台账号。

## 12. 上线前检查

开发完成后必须检查：

1. `index.html` 本地可打开。

2. 5 个页面都能打开。

3. 顶部导航链接有效。

4. 页脚链接有效。

5. 手机端 320px 宽度下不溢出。

6. 隐私政策页面清楚可读。

7. 支持页有真实反馈入口或明确 TODO 未上线。

8. 没有登录、支付、社区、AI 聊天入口。

9. 没有暴露任何 token、密钥或私密链接。

10. 页面内容与文档定位一致。

## 13. 安全规则

不要提交：

- API token。
- 飞书机器人 token。
- 飞书应用密钥。
- 私人手机号。
- 私人邮箱，除非用户明确要求公开。
- 未公开的下载链接。
- App 签名文件。
- 云服务密钥。
- `.env` 文件。

第一版静态站不应该需要任何密钥。

## 14. 后续扩展规则

如果后续要扩展以下能力，必须先单独规划：

- 博客系统。
- 文章列表。
- 网站访问统计。
- App 行为数据接口。
- 用户反馈接口。
- AI 功能。
- 付费功能。
- 用户自定义英语包。
- 音色服务。
- 内容包下载。

不要把这些能力夹带进第一版。

## 15. 推荐开发顺序

如果后续开始写网页源码，按以下顺序：

```text
1. 创建基础 HTML 文件
2. 创建统一 CSS
3. 开发首页
4. 开发润木听听产品页
5. 开发隐私政策页
6. 开发支持反馈页
7. 开发关于页
8. 检查移动端
9. 检查链接
10. 准备部署
```

隐私政策和支持页优先级高于视觉细节。

## 16. 与 Flutter App 的关系

`rmrm.me` 网站和 Flutter App 是两个项目。

网站可以引用 App 的：

- 产品名。
- 产品定位。
- App 图标。
- 隐私说明。
- 支持入口。

但网站不应该直接依赖 App 项目的：

- Flutter 代码。
- SQLite 数据库。
- 音频 assets。
- 测试文件。
- 构建配置。

后续迁出后，网站应能独立运行。

## 17. 完成汇报格式

后续 agent 完成网站相关任务后，建议按以下格式汇报：

```text
1. 修改了哪些文件
2. 如何本地打开
3. 如何检查移动端
4. 如何部署
5. 是否有遗留问题
```

如果只是文档任务，也要说明：

```text
本轮只修改 rmrm_me/ 内文档，未开发网页源码。
```

## 18. 一句话提醒

后续开发时请一直记住：

```text
rmrm.me 第一版要轻、清楚、可信。
不要把一个个人品牌入口做成复杂系统。
```

这也是最适合当前阶段的路线。
