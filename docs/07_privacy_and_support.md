# 隐私与支持要求

## 1. 文档目标

本文档用于约束 `rmrm.me` 网站第一版中的隐私政策页和支持反馈页。

这两个页面不是装饰页面，而是当前阶段最重要的基础设施之一。

它们需要同时服务：

- App 内测用户。
- 应用市场审核人员。
- 对隐私和权限敏感的家长。
- 后续产品迭代中的反馈收集。

第一版必须保证：

```text
privacy.html 可以作为隐私政策页面
support.html 可以作为支持与反馈页面
```

并且这两个页面都无需登录即可访问。

## 2. 页面和 URL 要求

### 2.1 隐私政策页面

静态文件：

```text
privacy.html
```

推荐线上 URL：

```text
https://rmrm.me/privacy
```

或：

```text
https://rmrm.me/privacy.html
```

App 内“关于”页面已经使用：

```text
rmrm.me/privacy
```

因此正式部署时，建议尽量支持无后缀路径 `/privacy`。

如果第一版暂时无法配置无后缀路径，也必须确保 `/privacy.html` 可以访问，并在 App 或应用市场资料中使用真实可访问链接。

### 2.2 支持与反馈页面

静态文件：

```text
support.html
```

推荐线上 URL：

```text
https://rmrm.me/support
```

或：

```text
https://rmrm.me/support.html
```

App 内“关于”页面已经使用：

```text
rmrm.me/support
```

因此正式部署时，建议尽量支持无后缀路径 `/support`。

### 2.3 可访问性要求

隐私政策和支持页必须满足：

- 不需要登录。
- 不需要验证码。
- 不需要关注公众号。
- 不需要下载 App。
- 不跳转到空白页。
- 手机浏览器可以正常打开。
- 页面文字清楚可读。
- 链接稳定。

应用市场审核人员可能只打开这两个链接，不会看完整网站。因此这两个页面必须独立完整。

## 3. 当前 App 隐私事实

隐私政策必须以 App 当前真实状态为准。

当前 App 是：

```text
润木听听
给英语一般的爸妈用的亲子英语包播放器
```

当前版本原则：

- 不登录。
- 不注册。
- 不做用户账号。
- 不做云同步。
- 不做社区。
- 不做评论。
- 不做 AI 聊天。
- 不做发音评分。
- 不做广告。
- 不接第三方分析 SDK。
- 不申请麦克风权限。
- 不申请定位权限。
- 不申请通讯录权限。
- 不申请相册权限。
- 不申请摄像头权限。
- 不申请推送通知权限。
- 收藏、播放记录、当前英语包、设置优先保存在本地设备。

当前 App 可能使用：

- 音频播放能力。
- 后台播放相关系统能力。
- 通知栏/锁屏媒体控制相关系统能力。

这些能力应在隐私政策中以“音频播放相关能力”说明，不要写成敏感数据收集。

## 4. 隐私政策必须包含的内容

`privacy.html` 至少应包含以下模块。

### 4.1 页面标题

```text
润木听听隐私政策
```

### 4.2 更新日期

例如：

```text
更新日期：2026 年 7 月 1 日
```

正式上线前需要确认日期。

### 4.3 我们是谁

说明：

```text
润木听听是一个给爸妈用的亲子英语包播放器，由润木同学制作。官方网站为 rmrm.me。
```

### 4.4 我们收集哪些信息

当前版本建议表达：

```text
当前版本不要求用户创建账号，不需要填写姓名、手机号、邮箱或孩子信息。

在没有接入匿名统计服务之前，App 不会主动上传你的使用行为数据。
```

如果未来接入匿名统计，必须删除或修改“不会主动上传使用行为数据”这一句。

### 4.5 本地保存的数据

说明 App 可能在本地保存：

- 收藏的句子。
- 当前英语包。
- 播放记录。
- 继续上次播放信息。
- 本地设置。

推荐表达：

```text
这些数据主要保存在你的设备本地，用于让 App 正常工作。
```

### 4.6 权限说明

必须说明当前不申请：

- 麦克风权限。
- 定位权限。
- 通讯录权限。
- 相册权限。
- 摄像头权限。
- 推送通知权限。

同时说明：

```text
App 可能会使用与音频播放相关的系统能力，以支持后台播放、通知栏播放控制或锁屏播放控制。
```

### 4.7 儿童信息

因为产品涉及亲子场景，必须明确：

```text
润木听听面向家长使用，不要求用户填写儿童姓名、年龄、照片、学校等个人信息。

请不要在反馈表中提交孩子的敏感个人信息。
```

### 4.8 第三方服务

当前版本建议表达：

```text
当前版本不接入广告 SDK，不接入第三方分析 SDK，也不接入第三方登录。

支持与反馈入口可能使用飞书表单。你通过飞书表单主动提交的内容，将用于问题排查和产品改进。
```

### 4.9 隐私政策更新

必须说明：

```text
如果后续 App 增加匿名统计、付费、用户自定义英语包、云端同步、音色服务或其他需要处理数据的能力，我们会更新本隐私政策。
```

### 4.10 联系方式

指向支持页：

```text
如果你对隐私政策有疑问，可以通过支持与反馈页面联系。
```

## 5. 隐私政策禁止写法

不要写与当前 App 不一致的内容。

禁止写：

```text
我们会收集你的通讯录
我们会收集你的地理位置
我们会访问你的相册
我们会使用麦克风进行发音评分
我们会基于你的学习行为生成报告
我们会向广告合作方共享数据
```

当前 App 没有做这些，不要写。

也不要写过度宽泛的条款，例如：

```text
我们可能收集你使用本服务过程中产生的所有信息。
```

这种写法会降低家长用户信任，也不符合当前极简产品原则。

## 6. 支持与反馈页面目标

`support.html` 的目标是帮助用户顺利反馈问题。

它不是客服中心，不是社区，不是工单系统。

第一版只需要做到：

```text
说明如何反馈
提供飞书表单入口
告诉用户反馈时提供哪些信息
回答几个常见问题
```

## 7. 反馈入口方案

第一版使用：

```text
飞书表单
```

原因：

- 不需要自建服务器。
- 不需要数据库。
- 不需要暴露飞书 API token。
- 可以结构化收集信息。
- 适合内测阶段。

不要在网页前端直接调用飞书 API。

不要把飞书机器人 token、应用密钥、API token 放到前端代码里。

支持页只放飞书表单的公开填写链接。

## 8. 飞书表单建议字段

飞书表单建议包含以下字段。

### 8.1 基础信息

- 手机型号。
- 系统版本。
- App 版本。
- 使用渠道。

示例：

```text
手机型号：华为 Mate 60
系统版本：HarmonyOS x.x
App 版本：1.0.0
```

### 8.2 问题类型

建议选项：

```text
播放问题
后台/锁屏问题
内容错误
界面不好用
收藏/搜索问题
英语包建议
其他
```

不要使用“学习问题”“课程问题”等学习平台词汇。

### 8.3 问题描述

字段说明：

```text
请描述你遇到的问题，尽量说明发生在哪个页面、正在播放哪个英语包或场景。
```

### 8.4 是否可以重复出现

选项：

```text
每次都会
偶尔出现
只出现过一次
不确定
```

### 8.5 联系方式

可选字段：

```text
如果方便，可以留下联系方式，便于进一步确认。
```

必须标注可选，不要强制收集。

### 8.6 敏感信息提醒

表单中应提醒：

```text
请不要提交孩子的姓名、照片、学校等敏感个人信息。
```

## 9. 支持页建议常见问题

支持页第一版可放 5 个常见问题。

### 9.1 为什么没有登录？

回答：

```text
当前版本优先做一个简单、本地可用的播放器。收藏、播放记录和设置优先保存在设备本地，因此暂时不需要登录。
```

### 9.2 为什么没有 AI 老师？

回答：

```text
润木听听当前不是 AI 英语老师，而是亲子英语包播放器。第一版优先保证内容和播放体验稳定。
```

### 9.3 为什么没有发音评分？

回答：

```text
这个 App 不是测评工具，也不希望给爸妈制造学习压力。当前重点是帮爸妈更快听到、找到、说出一句英语。
```

### 9.4 播放有问题怎么办？

回答：

```text
请通过反馈表告诉我手机型号、系统版本、App 版本，以及问题发生时正在播放的英语包或场景。
```

### 9.5 隐私政策在哪里？

回答：

```text
你可以访问 rmrm.me/privacy 查看隐私政策。
```

## 10. 支持页禁止事项

支持页不要做：

- 登录后提交工单。
- 在线客服系统。
- 评论区。
- 用户留言墙。
- 社区讨论。
- 用户公开反馈列表。
- 点赞。
- 排行榜。
- 分享广场。
- 复杂客服机器人。
- 付费咨询入口。

第一版只要飞书表单即可。

## 11. 应用市场审核注意事项

提交应用市场时，可能需要填写：

```text
官网 URL
隐私政策 URL
支持 URL
```

建议：

```text
官网 URL：https://rmrm.me
隐私政策 URL：https://rmrm.me/privacy
支持 URL：https://rmrm.me/support
```

如果无后缀路径未配置成功，则使用：

```text
隐私政策 URL：https://rmrm.me/privacy.html
支持 URL：https://rmrm.me/support.html
```

审核前必须确认这些链接：

- 可以打开。
- 不需要登录。
- 不是空页面。
- 没有 TODO 占位。
- 内容和 App 当前权限一致。

## 12. 后续接入匿名统计时的要求

当前第一版不接统计。

如果后续 App 或网站接入匿名统计，必须先更新：

- 隐私政策。
- App 关于页说明。
- 相关文档。

匿名统计也应遵守：

- 不收集姓名。
- 不收集手机号。
- 不收集孩子信息。
- 不收集精确位置。
- 不上传用户自定义内容。
- 不上传搜索文本。
- 不上传个人英语包内容。

如果只是为了内测判断基本打开和使用情况，优先收集最少事件。

例如：

```text
app_open
session_end
playback_start
playback_pause
playback_stop
pack_set_current
favorite_toggle
```

这些属于后续 App 侧功能，不属于第一版网站。

## 13. 后续接入付费或音色服务时的要求

如果后续加入：

- 英语包单独付费。
- 音色服务。
- 用户自定义英语包。
- 云端生成音频。
- 支付校验。

必须重新评估：

- 隐私政策。
- 用户协议。
- 数据处理说明。
- 第三方服务说明。
- 支付平台说明。
- 用户内容保存策略。

不要在第一版隐私政策里提前承诺尚未确定的云服务能力。

## 14. 支持反馈处理建议

内测阶段收到反馈后，建议手动分类：

```text
播放稳定性
后台/锁屏
内容错误
页面交互
英语包需求
隐私/权限疑问
其他
```

优先级建议：

1. 阻塞播放的问题。
2. 后台/锁屏播放问题。
3. 用户找不到暂停或继续播放入口的问题。
4. 内容错误。
5. 影响理解的界面问题。
6. 新功能建议。

当前阶段不要被太多新功能建议带偏。App 核心仍然是播放器。

## 15. 隐私和支持验收标准

上线前检查：

1. `privacy.html` 可以本地打开。

2. `support.html` 可以本地打开。

3. 页面移动端可读。

4. 隐私政策写明不登录、不注册。

5. 隐私政策写明不申请麦克风、定位、通讯录、相册、摄像头权限。

6. 隐私政策写明本地收藏、播放记录和设置。

7. 支持页有飞书表单入口。

8. 支持页提醒不要提交儿童敏感个人信息。

9. 页面没有暴露飞书 API token。

10. 页面没有登录、社区、支付、AI 聊天入口。

11. 内容与 App 当前真实状态一致。

## 16. 一句话结论

`rmrm.me` 第一版的隐私和支持策略是：

```text
隐私政策真实克制，
支持入口用飞书表单，
不自建后台，
不收集不必要信息，
不让用户为了反馈而登录。
```

这比复杂客服系统更适合当前阶段。
