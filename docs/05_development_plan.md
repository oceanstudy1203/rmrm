# 开发计划

## 1. 开发目标

`rmrm.me` 第一版开发目标是做一个轻量、可信、可上线的静态网站。

第一版不是复杂官网，不是博客系统，不是 App 后台，也不是在线产品平台。它只需要完成以下事情：

```text
讲清润木同学是谁
讲清润木听听是什么
提供隐私政策页面
提供支持与反馈页面
方便后续部署到 rmrm.me
```

第一版完成后，网站应能作为：

- 个人品牌主页。
- 润木听听产品说明页。
- 应用市场隐私政策 URL。
- 应用市场支持 URL。
- 内测用户反馈入口。

## 2. 技术路线

第一版推荐使用：

```text
纯 HTML
纯 CSS
少量 JavaScript
```

不要引入：

- React。
- Vue。
- Next.js。
- Nuxt。
- Astro。
- Vite。
- Tailwind。
- UI 组件库。
- 构建工具。
- Node 后端。
- 数据库。
- CMS。

原因：

- 当前页面很少。
- 第一版重点是上线和可信，不是工程复杂度。
- 纯静态文件便于迁移、部署、备份和长期维护。
- 后续如果真的需要博客或更多产品页，可以再升级技术栈。

少量 JavaScript 允许用于：

- 移动端菜单。
- 当前年份显示。
- 简单交互增强。

如果不用 JavaScript 也能完成，优先不用。

## 3. 推荐目录结构

后续开始开发网页源码时，建议使用以下结构：

```text
rmrm_me/
  index.html
  tingting.html
  about.html
  privacy.html
  support.html
  assets/
    css/
      style.css
    images/
      app-icon.png
      avatar.png
  docs/
    00_project_brief.md
    01_brand_positioning.md
    02_site_structure.md
    03_visual_design_direction.md
    04_page_copywriting.md
    05_development_plan.md
    06_deployment_plan.md
    07_privacy_and_support.md
    08_agent_work_rules.md
```

说明：

- 所有网站源码都放在 `rmrm_me/` 内。
- 不要修改 Flutter App 的 `web/` 目录。
- 不要把网站文档放到 App 项目的 `docs/` 目录。
- 后续整个 `rmrm_me/` 文件夹可以直接移出，作为独立项目。

## 4. 开发步骤总览

建议按以下顺序开发：

```text
1. 创建静态站基础结构
2. 准备图片资源
3. 编写统一 CSS
4. 开发首页 index.html
5. 开发润木听听产品页 tingting.html
6. 开发关于页 about.html
7. 开发隐私政策页 privacy.html
8. 开发支持反馈页 support.html
9. 检查移动端适配
10. 检查所有链接
11. 本地验收
12. 部署到 rmrm.me
```

开发时不要一次性追求完美。先保证页面能打开、内容清楚、移动端可读，再做视觉细节。

## 5. 第一步：创建静态站基础结构

创建文件：

```text
index.html
tingting.html
about.html
privacy.html
support.html
assets/css/style.css
assets/images/
```

每个 HTML 文件都应包含：

- `<!doctype html>`
- `html lang="zh-CN"`
- `meta charset="utf-8"`
- `meta viewport`
- 页面 `title`
- 页面 `description`
- 引用统一 CSS
- 顶部导航
- 主内容
- 页脚

所有页面应使用同一套导航和页脚，保持一致。

## 6. 第二步：准备图片资源

第一版可用图片：

- 润木听听 App 图标。
- 润木同学头像。

建议文件名：

```text
assets/images/app-icon.png
assets/images/avatar.png
```

图片使用原则：

- App 图标代表润木听听。
- 头像代表润木同学。
- 不要把头像和 App 图标混用。
- 不要大面积铺满图片。
- 如果没有合适图片，宁可先只用文字和卡片。

图片尺寸建议：

```text
app-icon.png    512x512 或 1024x1024
avatar.png      512x512 或 1024x1024
```

网页中显示时用 CSS 控制尺寸，不要直接使用过大的显示宽高。

## 7. 第三步：编写统一 CSS

统一 CSS 文件：

```text
assets/css/style.css
```

CSS 应包含：

- CSS reset 或基础归一化。
- 颜色变量。
- 字体设置。
- 页面容器。
- 顶部导航。
- 页脚。
- 按钮。
- 卡片。
- 文本页面排版。
- 移动端媒体查询。

推荐颜色变量：

```css
:root {
  --bg: #fbfaf7;
  --surface: #ffffff;
  --text: #17201b;
  --muted: #5f6b63;
  --border: #e4e8e2;
  --primary: #2e6f5e;
  --primary-dark: #1f5b4d;
  --wood: #b98555;
  --leaf: #8daa45;
}
```

推荐字体：

```css
body {
  font-family:
    -apple-system,
    BlinkMacSystemFont,
    "Segoe UI",
    "PingFang SC",
    "Microsoft YaHei",
    sans-serif;
}
```

CSS 原则：

- 不写复杂动画。
- 不写难维护的选择器。
- 不依赖 CSS 框架。
- 移动端优先。
- 页面不要横向滚动。
- 文本宽度保持舒适。

## 8. 第四步：开发首页 index.html

首页目标：

```text
讲清润木同学是谁，并自然引出润木听听。
```

首页模块顺序：

1. 顶部导航。
2. 首屏。
3. 当前作品：润木听听。
4. 我正在记录什么。
5. 为什么做这些。
6. 页脚。

首屏文案使用：

```text
润木同学

我在用 AI 做一些自己真的会用的小工具。

第一个作品是「润木听听」：
一个给爸妈用的亲子英语包播放器。
```

首页主按钮：

```text
了解润木听听
```

链接到：

```text
tingting.html
```

首页次按钮：

```text
支持与反馈
```

链接到：

```text
support.html
```

首页不放：

- 下载按钮。
- 购买按钮。
- 登录入口。
- 课程入口。
- AI 老师入口。

## 9. 第五步：开发润木听听产品页 tingting.html

产品页目标：

```text
讲清润木听听是什么、适合谁、不是什么，以及如何反馈。
```

模块顺序：

1. 顶部导航。
2. 产品首屏。
3. 它适合谁。
4. 它不是什么。
5. 怎么使用。
6. 当前内测版能力。
7. 隐私和数据。
8. 欢迎反馈。
9. 页脚。

产品首屏文案：

```text
润木听听

给英语一般的爸妈用的亲子英语包播放器。

它不是英语课程，不打卡、不测评，也不制造学习压力。

你可以像听音乐一样选择一个亲子英语包，在车上、家里、睡前听几句，然后试着对孩子说出来。
```

产品页主按钮：

```text
支持与反馈
```

产品页次按钮：

```text
查看隐私政策
```

不要放尚未确定的下载链接。如果后续确定内测下载方式，再单独加。

## 10. 第六步：开发关于页 about.html

关于页目标：

```text
让用户知道润木同学是一个真实的人，而不是无来源 App 发布者。
```

模块顺序：

1. 顶部导航。
2. 关于首屏。
3. 我是谁。
4. 为什么开始做个人开发。
5. 第一个产品：润木听听。
6. 我会记录什么。
7. 页底 CTA。
8. 页脚。

关于页语气：

- 真实。
- 克制。
- 不成功学。
- 不夸大。
- 不包装成专家。

关于页可以出现头像，但不要使用大面积头像背景。

## 11. 第七步：开发隐私政策页 privacy.html

隐私页目标：

```text
给用户和应用市场审核人员提供清楚、真实、可访问的隐私说明。
```

页面必须包含：

- 页面标题。
- 更新日期。
- 我们是谁。
- 我们收集哪些信息。
- 本地保存的数据。
- 权限说明。
- 儿童信息。
- 第三方服务。
- 隐私政策更新。
- 联系方式。

隐私页应使用单栏文本布局。

重点说明：

```text
当前版本不登录、不注册。
当前版本不申请麦克风、定位、通讯录、相册、摄像头权限。
收藏、播放记录、当前英语包和设置优先保存在本地设备。
当前版本不接广告 SDK，不接第三方分析 SDK。
```

如果未来接入匿名统计、付费、自定义英语包、云端能力或音色服务，必须更新隐私页。

## 12. 第八步：开发支持反馈页 support.html

支持页目标：

```text
让用户知道如何反馈内测问题。
```

模块顺序：

1. 顶部导航。
2. 支持首屏。
3. 填写反馈表按钮。
4. 反馈时建议提供的信息。
5. 常见问题。
6. 页脚。

主按钮：

```text
填写反馈表
```

链接暂用：

```text
# TODO: 替换为飞书表单链接
```

正式上线前必须替换成真实飞书表单链接。

支持页不要做：

- 在线客服。
- 登录工单。
- 评论区。
- 用户留言墙。
- 暴露飞书 API token。

## 13. 第九步：检查移动端适配

移动端重点检查：

- 320px 宽度是否可读。
- 375px 宽度是否舒服。
- 390px/414px 宽度是否正常。
- 顶部导航是否换行正常。
- 按钮是否容易点击。
- 图片是否溢出。
- 页面是否出现横向滚动。
- 隐私政策是否可读。

建议用浏览器开发者工具检查：

```text
iPhone SE
iPhone 12/13/14
常见 Android 宽度
```

## 14. 第十步：检查所有链接

需要检查：

- 顶部导航链接。
- 页脚链接。
- 首页按钮。
- 产品页按钮。
- 关于页按钮。
- 支持页反馈按钮。
- 隐私政策链接。

第一版内部链接应全部使用相对路径：

```text
index.html
tingting.html
about.html
privacy.html
support.html
```

这样即使本地双击打开，也能正常跳转。

部署后如需无后缀 URL，可以通过部署平台配置重写，不要让本地开发复杂化。

## 15. 第十一步：本地验收

本地验收方式：

1. 双击 `index.html`。

2. 逐个点击导航和按钮。

3. 用浏览器开发者工具切换移动端尺寸。

4. 检查所有页面标题和文案。

5. 检查没有 404。

6. 检查图片路径正确。

7. 检查隐私政策和支持页可以单独打开。

如果需要更接近线上环境，可以在 `rmrm_me/` 下启动一个简单静态服务器：

```powershell
python -m http.server 8080
```

然后访问：

```text
http://localhost:8080
```

这一步不是必须，但有助于检查路径问题。

## 16. 第十二步：部署准备

部署前确认：

- 飞书表单链接已替换。
- 隐私政策日期已更新。
- 没有假下载链接。
- 没有未完成 TODO 展示给用户。
- 所有页面 title 正确。
- 所有页面 description 正确。
- 图片资源已压缩到合理大小。
- 页面可在手机上正常阅读。

然后按 `06_deployment_plan.md` 进行部署。

## 17. 第一版验收标准

第一版完成后，应满足：

1. `index.html` 本地双击可打开。

2. 5 个页面都能互相访问。

3. 页面移动端可读。

4. 顶部导航和页脚清楚。

5. 首页能讲清润木同学。

6. 产品页能讲清润木听听。

7. 隐私政策页可以作为应用市场链接。

8. 支持页有飞书表单入口。

9. 不依赖后端。

10. 不依赖数据库。

11. 不需要构建工具。

12. 不新增登录、支付、社区、AI 聊天或广告。

## 18. 后续可扩展项

第一版上线后，如果确实需要，可以逐步扩展：

- 开发记录页。
- 作品集页。
- 内测招募页。
- App 截图区域。
- 常见问题独立页面。
- 简单文章列表。

但这些都不是第一版必须。

扩展前先确认：

```text
这个页面是否真的服务用户理解、反馈或信任？
```

如果只是因为“看起来更像官网”，可以先不做。

## 19. 禁止事项

后续开发人员或 agent 不要在第一版擅自添加：

- 登录。
- 注册。
- 用户系统。
- 评论。
- 社区。
- 点赞。
- 支付。
- 会员。
- 订阅。
- AI 聊天。
- 在线生成英语句子。
- 用户上传英语包。
- App 后台。
- 数据库。
- 复杂动画。
- 第三方分析 SDK。
- 广告。

本网站第一版只是静态信息站。

## 20. 一句话结论

开发时请始终记住：

```text
第一版 rmrm.me 不是为了显得复杂，
而是为了让用户相信这是一个真实、清楚、可以反馈的项目。
```

先轻量上线，再根据真实反馈迭代。
