# rmrm.me 网站项目简报

## 1. 项目背景

`rmrm.me` 是“润木同学”的个人品牌官网，也是 App 产品“润木听听”的官方落点。

当前阶段，润木同学已经具备以下基础元素：

- 域名：`rmrm.me`
- 全平台账号名：`润木同学`
- 第一个 App 产品：`润木听听`
- 产品品类：`亲子英语包播放器`
- 产品阶段：内测准备 / 小范围真机验证
- 运营方向：记录用 AI 做真实小工具的过程，并围绕第一个 App 获取真实用户反馈

这个网站的第一版，不应该被做成复杂公司官网，也不应该被做成内容平台、课程平台或在线工具站。它的第一任务是建立可信感，让用户、朋友、内测家长、应用市场审核人员打开后能快速理解：

```text
润木同学是谁？
润木听听是什么？
为什么要做这个 App？
如何查看隐私政策？
如何反馈问题？
```

## 2. 项目定位

网站第一版定位：

```text
润木同学的个人品牌主页 + 第一个产品「润木听听」的正式入口
```

这句话包含两个重点。

第一，`rmrm.me` 不是只服务一个 App 的临时页面。它承接的是“润木同学”这个长期身份。后续如果继续做其他小工具、AI 编程记录、产品复盘或跨境电商相关工具，`rmrm.me` 都可以继续承载。

第二，当前阶段网站必须把“润木听听”讲清楚。润木听听是第一个正式作品，也是目前最需要内测、反馈和应用市场基础页面支持的产品。

所以第一版网站的层级应是：

```text
润木同学
  -> 正在用 AI 做真实小工具
  -> 第一个作品：润木听听
  -> 查看产品 / 隐私政策 / 支持反馈
```

不要反过来把网站做成：

```text
润木听听官网
  -> 顺便介绍作者润木同学
```

因为这样会让网站过早绑定单一产品，不利于长期个人品牌运营。

## 3. 品牌关系

当前品牌关系必须保持清晰。

```text
润木同学 = 个人品牌 / 创作者账号 / 出品者
润木听听 = App 产品名
亲子英语包播放器 = 产品品类说明
rmrm.me = 官方网站 / 可信落点
```

推荐在网站中这样表达：

```text
润木同学做的第一个小工具：润木听听。
```

或：

```text
润木听听，由润木同学制作。
```

不要把“润木同学”和“润木听听”混成一个概念。

错误方向示例：

```text
润木同学是一款 App
润木听听是一个账号
润木 AI 老师
润木英语课程
润木儿童英语平台
```

这些表达会让用户误解项目性质，也会把产品带偏成学习平台或 AI 教育产品。

## 4. 网站第一版要解决的问题

第一版网站主要解决三个现实问题。

### 4.1 给内测用户一个可信落点

内测用户可能来自：

- 熟人推荐。
- 微信群。
- 小红书。
- 视频号。
- 抖音。
- App 内“关于”页面。
- 应用安装包说明。

他们打开网站后，不需要看到很复杂的商业包装，而是需要快速确认：

- 这是一个真实项目。
- 这个 App 不是乱七八糟的下载包。
- 作者是谁。
- App 解决什么问题。
- 如果遇到问题，该去哪里反馈。

因此网站第一版需要清楚、克制、可信。不要使用过度营销词，不要堆砌大话。

### 4.2 给应用市场审核提供基础页面

后续提交应用市场时，通常需要填写：

- 官方网站。
- 隐私政策 URL。
- 支持或反馈 URL。
- 应用介绍。
- 权限说明。

当前 App 内“关于”页面已经写入：

```text
网站：rmrm.me
反馈：rmrm.me/support
隐私政策：rmrm.me/privacy
版本：内测版 1.0.0
```

因此网站第一版必须至少提供：

```text
https://rmrm.me/
https://rmrm.me/privacy
https://rmrm.me/support
```

实际静态文件可以先命名为：

```text
index.html
privacy.html
support.html
```

部署时再根据平台规则配置无后缀访问，或接受 `.html` 后缀访问。第一版最重要的是页面内容真实、稳定、可访问。

### 4.3 给长期运营提供主页

润木同学后续的内容运营不应只围绕 App 功能更新，也可以包含：

- 非科班个人开发者的学习过程。
- 使用 AI 编程的真实经验。
- 跨境电商从业者如何做自己的小工具。
- 第一个 App 从想法到内测的过程。
- 用户反馈如何影响产品迭代。
- 做产品时踩过的坑。

但第一版网站不需要马上做博客系统。可以先把首页文案和关于页写好，让用户知道这个账号会长期记录这些内容。

## 5. 首页主线

首页建议主线：

```text
润木同学

我在用 AI 做一些自己真的会用的小工具。

第一个作品是「润木听听」：
一个给爸妈用的亲子英语包播放器。
```

这条主线有几个好处：

- 真实，不装成大公司。
- 能解释为什么一个非科班开发者也在做 App。
- 能承接 AI 编程个人开发者这个长期内容方向。
- 能自然引出润木听听。
- 不会把 App 包装成 AI 产品或英语课程。

首页不建议使用以下表达：

```text
AI 赋能家庭教育
重塑儿童英语学习
打造智能亲子教育生态
让每个孩子赢在起跑线
一站式英语学习解决方案
```

这些表达太重，也不符合产品当前阶段。

## 6. 润木听听的表达边界

润木听听在网站里的定义必须和 App 内保持一致。

推荐表达：

```text
润木听听是一个给英语一般的爸妈用的亲子英语包播放器。
```

补充表达：

```text
它不是英语课程，不打卡、不测评，也不制造学习压力。
你可以像听音乐一样选择一个亲子英语包，在车上、家里、睡前听几句，然后试着对孩子说出来。
```

不要使用：

```text
课程
学习平台
训练营
打卡
等级
测评
AI 老师
发音评分
儿童课程
英语启蒙体系
```

润木听听的产品灵魂是：

```text
爸妈先开口，孩子自然听见。
```

网站文案应该围绕“帮爸妈更容易开口”，而不是围绕“让孩子系统学英语”。

## 7. 第一版不做什么

为了避免网站第一版失控，明确不做以下内容：

- 不做博客系统。
- 不做内容管理后台。
- 不做用户登录。
- 不做注册。
- 不做评论。
- 不做社区。
- 不做在线英语包库。
- 不做在线播放器。
- 不做付费页面。
- 不做会员体系。
- 不做 AI 聊天。
- 不做在线生成英语句子。
- 不做用户上传。
- 不做复杂动画。
- 不做数据看板。
- 不做自建反馈接口。
- 不做数据库。

第一版只需要让用户清楚地知道：

```text
这是谁？
在做什么？
第一个产品是什么？
隐私政策在哪里？
问题如何反馈？
```

## 8. 第一版成功标准

第一版网站完成后，应满足以下标准：

1. 用户打开首页后，能在 5 秒内理解“润木同学”是一个真实个人创作者身份。

2. 用户能从首页进入“润木听听”产品页，并理解这是一个亲子英语包播放器，不是课程 App。

3. 应用市场审核人员能访问隐私政策页和支持反馈页。

4. 网站在手机上阅读清楚，按钮和链接容易点击。

5. 网站没有引入登录、社区、支付、数据库、复杂后台。

6. 网站可以作为后续长期运营的起点，而不是一次性临时页面。

## 9. 当前阶段结论

当前最科学的做法不是先投入复杂网站建设，而是先做一个轻量、可信、能上线的静态站。

建议路线：

```text
先做静态站
-> 服务内测和应用市场基础审核
-> 观察 App 内测反馈和个人账号内容方向
-> 再决定是否扩展文章、作品集、数据接口或更多产品页面
```

`rmrm.me` 第一版应该稳一点、小一点、真实一点。它不是为了证明项目多大，而是为了让用户相信：这个产品背后有一个认真做事的人。
