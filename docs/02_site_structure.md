# 网站结构规划

## 1. 总体结构

`rmrm.me` 第一版采用 5 页静态站结构。

```text
index.html      润木同学首页
tingting.html   润木听听产品页
about.html      关于润木同学
privacy.html    隐私政策
support.html    支持与反馈
```

第一版不做多级导航，不做复杂栏目，不做文章系统。导航要非常简单，让用户在手机上也能快速理解网站结构。

推荐顶部导航：

```text
润木同学
润木听听
关于
支持
```

隐私政策可以放在页脚，不一定放在顶部主导航。

推荐页脚链接：

```text
润木听听
关于润木同学
支持与反馈
隐私政策
```

第一版所有页面都应能互相跳转，尤其要保证以下路径明确：

```text
首页 -> 润木听听产品页
首页 -> 支持与反馈
首页 -> 隐私政策
润木听听产品页 -> 支持与反馈
润木听听产品页 -> 隐私政策
```

## 2. index.html：润木同学首页

### 2.1 页面目标

首页的目标不是把所有信息讲完，而是在最短时间内建立信任，让用户知道：

```text
这是润木同学的个人主页。
他正在用 AI 做真实小工具。
第一个作品是润木听听。
```

首页要服务两个用户群：

1. 对“润木同学”感兴趣的人。
2. 被“润木听听”吸引过来的内测用户或家长。

首页要同时承接个人品牌和产品入口，但优先级是个人品牌在前，产品承接在后。

### 2.2 核心用户

首页主要面向：

- 从社交平台点进来的用户。
- 朋友、熟人、潜在内测用户。
- 对 AI 编程和个人开发感兴趣的人。
- 想确认 App 背后是谁的家长。
- 应用市场审核人员。

这些用户不是来阅读长篇论文的。他们需要快速确认：

- 你是谁。
- 你在做什么。
- 这个网站是否可信。
- 能不能找到 App、隐私政策和反馈入口。

### 2.3 首屏内容

首页首屏建议内容：

```text
润木同学

我在用 AI 做一些自己真的会用的小工具。

第一个作品是「润木听听」：
一个给爸妈用的亲子英语包播放器。
```

首屏按钮建议：

```text
了解润木听听
查看支持与反馈
```

如果只有一个主按钮，优先使用：

```text
了解润木听听
```

首屏可以使用一个轻量视觉元素：

- 润木听听 App 图标。
- 润木同学头像的小尺寸版本。
- 简洁的产品卡片。

不要使用大面积复杂插画，不要让视觉元素抢走文案重点。

### 2.4 页面模块

首页建议模块顺序：

1. 首屏介绍。

   说明润木同学是谁，正在做什么，第一个产品是什么。

2. 当前作品：润木听听。

   简短介绍产品：

   ```text
   给英语一般的爸妈用的亲子英语包播放器。
   ```

   配一个进入产品页的按钮。

3. 我正在记录什么。

   三个方向即可：

   ```text
   AI 编程个人开发
   第一个 App 从 0 到内测
   跨境电商从业者做小工具
   ```

4. 为什么做这些。

   简短说明：

   ```text
   我希望用 AI 把一些真实的小需求做成可以用的产品，而不是只停留在想法里。
   ```

5. 页脚。

   放产品、关于、支持、隐私政策链接。

### 2.5 CTA

首页主 CTA：

```text
了解润木听听
```

首页次 CTA：

```text
支持与反馈
```

不建议首页第一版放：

```text
立即下载
立即购买
加入会员
开始学习
免费领取课程
```

当前阶段更适合“了解”和“反馈”，不适合强销售。

### 2.6 不应该出现的内容

首页不要出现：

- 复杂产品矩阵。
- 大段商业计划。
- 课程销售文案。
- AI 教育平台文案。
- 用户注册入口。
- 付费入口。
- 公众号强制关注。
- 复杂动态效果。
- 看起来像培训机构的口号。

首页要克制，让用户觉得这个项目真实、轻、可信。

## 3. tingting.html：润木听听产品页

### 3.1 页面目标

产品页的目标是把“润木听听”讲清楚。

用户打开产品页后，应能理解：

```text
润木听听是什么？
它适合谁？
它不是什么？
它能帮我做什么？
如何反馈？
隐私政策在哪里？
```

产品页不需要做成长篇销售页。它应该像一个清晰、温和、可信的产品说明页。

### 3.2 核心用户

产品页主要面向：

- 有孩子的家长。
- 英语基础一般或零基础的家长。
- 想给孩子一点英语环境，但不知道怎么开口的人。
- 内测用户。
- 应用市场审核人员。
- 从 App 关于页点到网站的人。

### 3.3 首屏内容

产品页首屏建议：

```text
润木听听

给英语一般的爸妈用的亲子英语包播放器。

它不是英语课程，不打卡、不测评，也不制造学习压力。
你可以像听音乐一样选择一个亲子英语包，在车上、家里、睡前听几句，然后试着对孩子说出来。
```

按钮建议：

```text
查看支持与反馈
查看隐私政策
```

如果后续有下载链接，再增加：

```text
参与内测
```

但第一版如果还没有稳定分发方式，不要放假下载按钮。

### 3.4 页面模块

产品页建议模块顺序：

1. 产品首屏。

   产品名、品类说明、一句话价值。

2. 它适合谁。

   建议列出：

   - 有孩子的爸妈。
   - 英语一般或零基础。
   - 想在生活里说几句英语。
   - 不想打开复杂学习 App。

3. 它不是什么。

   建议明确：

   - 不是英语课程。
   - 不是打卡工具。
   - 不是发音评分。
   - 不是 AI 英语老师。
   - 不是儿童学习平台。

4. 它怎么使用。

   用简单路径表达：

   ```text
   选择英语包 -> 开始播放 -> 听到一句 -> 试着说出来
   ```

   或：

   ```text
   想说 -> 找到 -> 听到 -> 说出
   ```

5. 当前内测版能力。

   可以列出：

   - 官方英语包。
   - 聆听模式。
   - 跟读模式。
   - 播放英语包。
   - 播放场景。
   - 收藏常用句。
   - 本地搜索。
   - 后台播放。

6. 隐私和数据。

   简短说明：

   ```text
   当前版本不登录，不收集通讯录、定位、相册、摄像头或麦克风数据。收藏、播放记录和设置优先保存在本地设备。
   ```

7. 支持与反馈。

   引导用户去 `support.html`。

### 3.5 CTA

产品页主 CTA：

```text
支持与反馈
```

如果内测分发方式稳定后，主 CTA 可以改成：

```text
参与内测
```

产品页次 CTA：

```text
查看隐私政策
```

### 3.6 不应该出现的内容

产品页不要出现：

- 课程购买。
- 会员。
- VIP。
- AI 老师。
- 发音评分。
- 学习报告。
- 排行榜。
- 社区。
- 打卡。
- 在线生成句子。
- 用户上传英语包。
- 英语包市场。

即使这些功能未来可能出现，第一版产品页也不要提前承诺。

## 4. about.html：关于润木同学

### 4.1 页面目标

关于页的目标是让用户知道润木同学是一个真实的人，而不是无来源的 App 发布者。

关于页要表达：

- 非编程科班出身。
- 当前从事跨境电商。
- 平时使用 AI 做自动化、数据清洗、看板和小工具。
- 正在尝试用 AI 辅助开发个人产品。
- 润木听听是第一个 App。

### 4.2 核心用户

关于页主要面向：

- 对作者感兴趣的人。
- 潜在内测用户。
- 社交平台粉丝。
- 个人开发者同路人。
- 应用市场审核人员。

### 4.3 首屏内容

关于页首屏建议：

```text
关于润木同学

我是润木同学，非编程科班出身，目前从事跨境电商。
我正在用 AI 辅助开发一些自己真的会用的小工具。
```

可以放一张小头像，但不要铺满页面。

### 4.4 页面模块

关于页建议模块：

1. 我是谁。

   简短介绍背景。

2. 为什么开始做个人开发。

   说明 AI 编程带来的变化，以及做小工具的动机。

3. 第一个产品。

   介绍润木听听为什么开始。

4. 我会记录什么。

   - AI 编程。
   - 产品内测。
   - 真实反馈。
   - 跨境电商工具化思考。

5. 联系和反馈。

   链接到支持页。

### 4.5 CTA

关于页主 CTA：

```text
了解润木听听
```

次 CTA：

```text
支持与反馈
```

### 4.6 不应该出现的内容

关于页不要写成：

- 成功学故事。
- 创业融资介绍。
- 大公司愿景。
- 技术专家履历包装。
- 过度自夸。

真实比宏大更重要。

## 5. privacy.html：隐私政策

### 5.1 页面目标

隐私政策页的目标是：

- 给 App 用户解释数据和权限情况。
- 给应用市场审核提供可访问 URL。
- 明确当前 App 不做哪些数据收集。

这是一个功能性页面，不需要过度设计，但必须清楚、严谨、可访问。

### 5.2 核心用户

隐私政策页主要面向：

- App 用户。
- 内测用户。
- 应用市场审核人员。
- 对数据安全敏感的家长。

### 5.3 首屏内容

隐私页首屏建议：

```text
润木听听隐私政策

润木听听是一个亲子英语包播放器。当前版本以本地使用为主，不登录、不注册，不主动收集通讯录、定位、相册、摄像头或麦克风数据。
```

### 5.4 页面模块

隐私页建议模块：

1. 我们是谁。

   说明润木听听由润木同学制作，网站为 `rmrm.me`。

2. 我们收集什么。

   当前版本可写：

   ```text
   当前版本不需要用户注册或登录。
   ```

   如果没有接入统计 SDK，不要写会收集设备信息。

3. 本地数据。

   说明收藏、播放记录、当前英语包、设置等保存在本地设备。

4. 权限说明。

   说明不申请麦克风、定位、通讯录、相册、摄像头等敏感权限。

5. 儿童信息。

   说明不要求填写儿童姓名、年龄、照片等个人信息。

6. 第三方服务。

   当前如果不接第三方分析 SDK 和广告 SDK，就明确说明。

7. 联系方式。

   链接到支持页。

8. 更新日期。

   页面底部写：

   ```text
   更新日期：YYYY-MM-DD
   ```

### 5.5 CTA

隐私页 CTA 不需要太强。

页底放：

```text
如有问题，请通过支持与反馈页面联系。
```

### 5.6 不应该出现的内容

隐私页不要写：

- 实际没有做的数据收集。
- 实际没有接入的第三方服务。
- 含糊的“我们可能收集大量信息”。
- 与当前 App 状态不一致的条款。

如果后续接入匿名统计、付费、用户自定义英语包、云端同步或音色服务，必须更新隐私页。

## 6. support.html：支持与反馈

### 6.1 页面目标

支持页的目标是让用户知道如何反馈问题。

当前阶段，支持页对内测非常重要。它不是客服系统，而是轻量反馈入口。

### 6.2 核心用户

支持页主要面向：

- 内测用户。
- 遇到播放问题的用户。
- 想提出内容建议的用户。
- 应用市场审核人员。

### 6.3 首屏内容

支持页首屏建议：

```text
支持与反馈

如果你在使用润木听听时遇到播放、内容或界面问题，欢迎通过反馈表告诉我。
```

主按钮：

```text
填写反馈表
```

### 6.4 页面模块

支持页建议模块：

1. 反馈入口。

   放飞书表单链接。

2. 反馈建议。

   告诉用户尽量提供：

   - 手机型号。
   - 系统版本。
   - App 版本。
   - 问题发生在哪个页面。
   - 正在播放哪个英语包或场景。
   - 问题是否可以重复出现。

3. 常见问题。

   第一版可以只放 3 到 5 条：

   - 为什么没有登录？
   - 为什么没有 AI 老师？
   - 为什么没有发音评分？
   - 播放问题如何反馈？
   - 隐私政策在哪里？

4. 联系方式。

   可选放邮箱占位或社交账号说明。

### 6.5 CTA

支持页主 CTA：

```text
填写反馈表
```

次 CTA：

```text
查看隐私政策
```

### 6.6 不应该出现的内容

支持页不要做：

- 在线客服系统。
- 登录后提交工单。
- 评论区。
- 社区讨论。
- 用户公开留言墙。
- 暴露飞书 API token。

第一版用飞书表单就够了。

## 7. 全站导航建议

### 7.1 顶部导航

桌面端：

```text
左侧：润木同学
右侧：润木听听 / 关于 / 支持
```

移动端：

第一版可以不做复杂汉堡菜单。如果导航项少，可以直接横向排布或换行。

推荐移动端顺序：

```text
润木听听
关于
支持
```

隐私政策放页脚。

### 7.2 页脚

页脚建议包含：

```text
© 2026 润木同学
润木听听
关于
支持与反馈
隐私政策
rmrm.me
```

页脚不要堆太多链接。

## 8. 第一版不做的页面

第一版暂不创建：

- blog.html
- posts.html
- pricing.html
- login.html
- dashboard.html
- tools.html
- app-download.html
- analytics.html
- admin.html

原因：

- 当前核心目标是内测可信入口。
- 内容运营还没有稳定栏目。
- 付费和下载分发还没有最终确定。
- 个人开发者第一版应避免维护负担过重。

## 9. 页面完成验收标准

后续开发网页时，每个页面都应满足：

1. 双击 HTML 文件可以本地打开。

2. 页面不依赖构建工具。

3. 手机宽度下文字不溢出，按钮可点击。

4. 顶部导航和页脚链接有效。

5. 页面没有登录、社区、支付、AI 聊天、广告入口。

6. 文案与“润木同学 / 润木听听 / 亲子英语包播放器”的品牌关系一致。

7. 隐私页和支持页可以作为应用市场填写链接使用。

## 10. 一句话结论

第一版网站结构要保持轻：

```text
一个首页讲清润木同学，
一个产品页讲清润木听听，
一个关于页建立真实感，
一个隐私页服务审核和用户信任，
一个支持页收集内测反馈。
```

不要让网站第一版变成复杂项目。
